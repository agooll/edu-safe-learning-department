# 架构与失败路径

## 总体架构

```mermaid
flowchart LR
    U[学生 / 教师 / 监护人 / 管理者请求] --> X{AstronClaw L2 返回拦截}
    X -. 当前未验证 .-> C[中央控制器 start]
    C --> P{生成前预检}
    P -->|澄清 / 阻断 / 升级| Z[终止自动业务输出]
    P -->|允许且为学生| S[校验或初始化学习状态]
    P -->|允许且为其他角色| R[唯一主责路由]
    S --> R
    R --> T[唯一业务 Skill 生成 draft]
    T --> C1[控制器 submit-draft]
    C1 --> Q[独立质量审校]
    Q --> C2[控制器 submit-quality]
    C2 -->|返修，最多 2 次| T
    C2 -->|阻断 / 升级| Z
    C2 -->|最终门禁通过| A[ready-for-release]
    A --> C3[控制器 release]
    C3 --> O[仅原样返回 safe_output]
    C --> H[(SHA-256 链式回执与状态)]
    C1 --> H
    C2 --> H
    C3 --> H
    H --> V[verify 完整性校验]
    V -->|失败| Z
    O -->|主线证据| S
    S -->|completed| N[学习笔记候选]
    N --> C
    O -->|插问结论| B[逐层恢复主线]
```

图中的 AstronClaw L2 返回拦截是部署验收目标，不是当前 Skill 包已经具备的平台能力。当前包已实现 L1 控制器；平台是否能强制首调用和阻断直接回复必须按 `platform-enforcement.md` 实机验证。

## 学习闭环

```mermaid
flowchart LR
    G[目标确认] --> D[基线诊断]
    D --> E[知识讲解]
    E --> P[引导练习]
    P --> F[反馈]
    F -->|存在缺口| R[针对性重试]
    R --> P
    F -->|练习通过| T[迁移验证]
    T -->|未通过| E
    T -->|通过| S[延迟复习]
    S -->|遗忘| R
    S -->|通过| C[阶段完成]
```

## 长期保持闭环

```mermaid
flowchart LR
    N[结课笔记] --> V{时间戳与笔记完整性校验}
    V -->|失败| H[停止调度并人工检查]
    V -->|通过| M[生成七项绝对时间提醒清单]
    M --> A{学习者授权且定时任务可用？}
    A -->|是| T[注册一次性任务并绑定平台回执]
    A -->|否| I[降级为每次交互检查并明确告知]
    T --> D{最早未处理检查点是否到期}
    I --> D
    D -->|否| W[不打断当前主线]
    D -->|是| C{用户选择}
    C -->|跳过本次| S[留痕且 mastery_claimed=false]
    C -->|立即复习| R[按检查点执行主动检索或迁移]
    R -->|通过| P[进入下一个绝对检查点]
    R -->|有缺口| B[保留当前检查点并回流补救]
    S --> P
```

## 插问与恢复

```mermaid
flowchart LR
    A[主线学习] --> B[保存去标识化快照]
    B --> C[push 插问分支]
    C --> D[完整安全任务闭环]
    D --> E{继续插问？}
    E -->|嵌套插问| B
    E -->|返回| F[生成分支总结]
    F --> G[pop 一层分支]
    G --> H[展示完整恢复卡]
    H --> I[继续原唯一下一动作]
```

业务 Skill、质量审校和门禁均不直接向用户发布。插问分支可以解释概念，但不能推进主线学习阶段。

## 鲁棒性策略

- 单一主责：每轮只有一个主业务 Skill。
- 单一 L1 入口：所有用户可见业务输出必须由中央控制器创建工作流并取得发布授权。
- 链式回执：步骤、artifact、工作流和上一回执相互绑定，篡改或缺失即失败关闭。
- 独占状态：阶段监控、插问栈、笔记归档、长期复习计划和输出发布权分别归属不同组件。
- 机器可读交接：每一阶段都能独立验证和重试。
- 有界返修与分支：返修最多两次，插问嵌套最多八层。
- 失败关闭：异常、损坏、冲突和证据不足都不等于通过。
- 可解释裁决：只记录稳定规则代码和去标识化摘要。
- 人机协同：高影响任务不自动执行，保留教师最终权力。

## 模型与工具分工

- 输入预检、路由建议、状态转换、插问栈、时间戳校验、复习调度、结构校验和打包检查优先运行随包的确定性 Python 脚本。
- 教学设计、开放题评阅、学情解释和个性化规划使用具备良好中文与推理能力的模型；低置信度必须披露。
- 质量审校与业务生成保持独立，避免业务 Skill 自行批准草稿。
- 默认工具白名单仅包含读取本 Skill 文件和运行随包脚本。检索公开资料必须保留来源；写入成绩、发送消息和修改外部系统需要明确授权及人工确认。
- 平台定时任务属于外部状态变更：仅在 `reminder_policy: scheduled` 时创建；必须保存平台返回的任务 ID，失败时降级而不伪造成功。
- L2 平台约束不由 Skill 文档自动产生：只有必选工具、固定工作流或返回拦截器通过实机绕过测试后，才可宣称平台强制。
